# 底盘电机集成测试指南

本文档用于验证底盘控制链路。当前工程需要区分两条链路：

1. **当前主链路**：`Decision_making_task -> FreeRTOS Queue -> Chassis_control_task -> Chassis_Update_Control -> Djimotor_Calc_Output -> Motor_control_task -> CAN`
2. **历史测试链路**：`chassis_motor_integration_test -> Message_Center("chassis_cmd")`

当前 `Chassis_control_task.c` 从 `Chassis_cmd_queue_handle` 读取命令，不会自动订阅 `Message_Center` 的 `chassis_cmd` 话题。因此，旧的 `chassis_motor_integration_test.c` 不能直接代表当前主链路，除非额外增加桥接逻辑或把测试任务改为写队列。

## 当前主链路

```mermaid
flowchart LR
    DM["Decision_making_task"]
    Q["Chassis_cmd_queue_handle"]
    CT["Chassis_control_task"]
    CH["Chassis_Update_Control"]
    DJI["Djimotor_Calc_Output"]
    MT["Motor_control_task"]
    CAN["CAN1 0x200"]

    DM --> Q --> CT --> CH --> DJI --> MT --> CAN
```

主链路中：

- 决策层使用 `xQueueOverwrite(Chassis_cmd_queue_handle, &chassis_cmd_send)`。
- 底盘任务使用 `xQueueReceive(Chassis_cmd_queue_handle, &cmd_recv, 100)`。
- 100 tick 内未收到新命令时，底盘任务会进入 `CHASSIS_ZERO_FORCE`。
- 电机任务 1 ms 周期统一调用 `Djimotor_Send_All_Bus()`。

## 推荐测试方式

### 方式 A：使用当前决策任务测试

这是最贴近整车真实运行的方式。

前置条件：

- `Robot_task_init()` 中已创建 `Decision_making_task`、`Chassis_control_task`、`Motor_control_task`。
- 遥控器或图传链路数据正常。
- 急停未触发。
- 底盘架空。

测试步骤：

1. 上电后保持急停，确认四个底盘电机无输出。
2. 解除急停，保持摇杆/键盘无输入，确认底盘静止。
3. 低速给 `vx`，确认左右/前后方向符合预期。
4. 低速给 `vy`，确认横移方向符合预期。
5. 给小 `wz` 或切换 `CHASSIS_ROTATE`，确认旋转方向。
6. 切到 `CHASSIS_FOLLOW_GIMBAL`，缓慢转云台，确认底盘能跟随归中。

判定：

- 没有电机离线、CAN 邮箱长时间满、Fatal 急停。
- 电机方向与底盘坐标约定一致。
- 松开输入后底盘能稳定停下。

### 方式 B：使用队列写入测试任务

如果只想绕过遥控器和决策层测试底盘，可以新增或临时启用一个测试任务，直接写 `Chassis_cmd_queue_handle`。

参考逻辑：

```c
extern QueueHandle_t Chassis_cmd_queue_handle;

void Chassis_queue_test_task(void const *argument)
{
    Chassis_cmd_send_t cmd = {0};
    cmd.chassis_mode = CHASSIS_NO_FOLLOW;

    for (;;) {
        cmd.vx = 300.0f;
        cmd.vy = 0.0f;
        cmd.wz = 0.0f;
        xQueueOverwrite(Chassis_cmd_queue_handle, &cmd);
        osDelay(10);
    }
}
```

注意：这是测试思路，不建议长期保留在正式上车分支中。启用时要避免与 `Decision_making_task` 同时写同一个命令队列。

### 方式 C：使用历史 Pub/Sub 测试任务

文件：

```text
4-Application_Layer/For_Testing_Task/chassis_motor_integration_test.c
```

当前代码会：

```c
Publisher_t *chassis_cmd_pub = Pub_register("chassis_cmd", sizeof(Chassis_cmd_send_t));
Pub_push_message(chassis_cmd_pub, &cmd);
```

它适合验证 `Message_Center` 发布是否正常，但不能直接驱动当前 `Chassis_control_task`。如果要使用它测试底盘主链路，需要补一个订阅者桥接到 `Chassis_cmd_queue_handle`，或改成方式 B 的队列写入。

## 底盘模块预期配置

当前 `Chassis_init()` 初始化：

| 电机 | 名称 | CAN | 控制帧 | 反馈 ID |
| --- | --- | --- | --- | --- |
| 0 | `CHASSIS_FR` | CAN1 | `0x200` | `0x201` |
| 1 | `CHASSIS_FL` | CAN1 | `0x200` | `0x202` |
| 2 | `CHASSIS_BL` | CAN1 | `0x200` | `0x203` |
| 3 | `CHASSIS_BR` | CAN1 | `0x200` | `0x204` |

底盘类型当前为 `CHASSIS_TYPE_OMNI`。

## 推荐测试阶段

| 阶段 | 模式 | 指令 | 目的 |
| --- | --- | --- | --- |
| 0 | `CHASSIS_ZERO_FORCE` | `vx=vy=wz=0` | 确认安全失能 |
| 1 | `CHASSIS_NO_FOLLOW` | 小 `vx` | 验证左右/前后轮序和方向 |
| 2 | `CHASSIS_NO_FOLLOW` | 小 `vy` | 验证横移方向 |
| 3 | `CHASSIS_NO_FOLLOW` | 小 `wz` | 验证旋转方向 |
| 4 | `CHASSIS_FOLLOW_GIMBAL` | `offset_angle` 缓慢变化 | 验证跟随 PID 和云台零位 |
| 5 | `CHASSIS_ROTATE` | 小陀螺 | 验证固定旋转和坐标变换 |
| 6 | 功率限制开启 | 逐步增大速度 | 验证功率计和限功逻辑 |

## 观测点

### 软件观测

- `ERROR_WARN/ERROR_RAISE/ERROR_CRITICAL` 是否频繁出现。
- `Can_send_data()` 是否因为邮箱满长期失败。
- `Djimotor_get_status()` 是否为 `MOTOR_ENABLED`。
- `Djimotor_get_measure()` 的转速和电流是否随目标变化。
- `Chassis_feedback_queue_handle` 是否有更新。

### 硬件观测

- 电机方向是否符合轮位。
- 底盘架空时是否有异常震动。
- 落地低速时是否跑偏。
- 功率限制打开后是否出现明显削顶。

## 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 历史测试任务发布了但底盘不动 | 测试任务使用 Message Center，主底盘任务读 Queue | 使用方式 A/B，或增加桥接 |
| 电机全部无输出 | `Motor_control_task` 未运行、CAN 未启动、急停未解除 | 检查任务创建和 `Can_init()` |
| 单个电机无反馈 | ID/接线/电源错误，或 CAN LUT 未注册 | 检查 `rx_id` 和电机拨码 |
| 方向整体反了 | 坐标系符号约定与机械安装相反 | 先改测试目标符号，再决定是否改运动学 |
| 跟随模式乱转 | `YAW_CHASSIS_ALIGN_ECD` 或 `CHASSIS_FORWARD_ANGLE` 未标定 | 重新标定云台零位和底盘前向 |
| 速度忽快忽慢 | S 曲线、功率限制或 PID 参数影响 | 分别关闭/降低目标排查 |

## 安全注意

- 测试底盘前务必架空或限位。
- 一次只让一个任务写 `Chassis_cmd_queue_handle`。
- 首次测试目标量从小到大。
- 不要在电机异常发热、CAN 错误频繁或遥控器离线时继续场地测试。
