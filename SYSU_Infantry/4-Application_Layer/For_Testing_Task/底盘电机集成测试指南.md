# 底盘-电机集成测试文档

## 概述
本文档详细描述了如何对新开发的底盘->话题数据->电机驱动框架进行全面测试。测试框架设计为独立运行，不污染主系统，同时提供完整的数据流验证。

## 测试架构

### 测试组件
```
测试任务 (Integration Test Task)
    ↓ 模拟决策层指令
Chassis Task (底盘任务)
    ↓ 静态全局变量
Motor Task (电机任务)
    ↓ 电机控制
DJI Motor Driver (电机驱动)
```

### 数据流验证点
1. **消息发布** - 测试任务 → Chassis Task
2. **运动学解算** - Chassis Task 内部验证
3. **数据传递** - Chassis Task → Motor Task (静态全局变量)
4. **电机控制** - Motor Task → DJI电机驱动
5. **反馈回环** - Chassis Task → 测试任务

## 测试阶段详解

### 阶段1：初始化测试 (TEST_INIT)
**目标**: 验证系统基础组件正常工作

**测试步骤**:
1. 检查消息中心注册是否成功
2. 验证发布者和订阅者创建
3. 发送停止指令确保初始状态
4. 验证任务创建和启动

**预期结果**:
- 消息中心注册成功
- 底盘任务和电机任务正常启动
- 初始状态设置为零力矩模式

**验证方法**:
```c
if (chassis_cmd_pub && chassis_feedback_sub) {
    TEST_LOG("✓ Message center registration successful");
}
```

### 阶段2：静态值测试 (TEST_STATIC_VALUES)
**目标**: 验证固定控制指令的传递和执行

**测试用例**:
1. 纯前进运动 (vx=1.0, vy=0, wz=0)
2. 纯横移运动 (vx=0, vy=1.0, wz=0)
3. 纯旋转运动 (vx=0, vy=0, wz=1.0)
4. 复合运动 (vx=0.5, vy=0.5, wz=0.5)

**验证点**:
- 底盘反馈数据正确性
- 电机速度设置有效性
- 电机模式切换正确性

**预期结果**:
```
Testing: Forward movement
Sent chassis command: vx=1.00, vy=0.00, wz=0.00, mode=1 -> 1 subscribers
Received chassis feedback: wz=0.00 (expected: 0.00)
✓ Chassis feedback validation passed
Current motor speeds: [0.0, 13.2, 0.0, -13.2]
✓ Motor speeds validation passed
```

### 阶段3：动态运动测试 (TEST_DYNAMIC_MOVEMENT)
**目标**: 验证连续变化的控制指令处理能力

**测试模式**:
- 正弦波运动模式
- 实时更新控制指令
- 验证数据流的连续性

**测试公式**:
```c
float time = phase_counter * 0.1f;
float vx = sin(time) * 0.5f;
float vy = cos(time) * 0.5f;
float wz = sin(time * 0.5f) * 0.3f;
```

**验证点**:
- 动态指令响应速度
- 数据传递延迟
- 电机速度的连续更新

### 阶段4：模式切换测试 (TEST_MODE_SWITCHING)
**目标**: 验证不同底盘模式的切换和执行

**测试模式**:
1. `CHASSIS_ZERO_FORCE` - 零力矩模式
2. `CHASSIS_NO_FOLLOW` - 不跟随模式
3. `CHASSIS_FOLLOW_GIMBAL` - 跟随云台模式
4. `CHASSIS_ROTATE` - 小陀螺模式

**验证点**:
- 模式切换的正确性
- 不同模式下的电机行为
- PID参数的正确加载

**预期结果**:
```
Testing mode: FOLLOW_GIMBAL
Current motor mode: 2 (expected: 2)
✓ Motor mode validation passed
```

### 阶段5：运动学解算验证 (TEST_KINEMATICS)
**目标**: 验证底盘运动学解算的正确性

**测试场景**:
1. 纯前进 - 验证前后电机转动方向
2. 纯横移 - 验证左右电机转动方向
3. 纯旋转 - 验证所有电机同方向转动

**验证方法**:
- 检查电机转速的符号正确性
- 验证运动学模型的数学实现
- 确认轮子转动方向符合预期

**预期模式** (全向轮):
```
纯前进: [0, +, 0, -] (前后电机)
纯横移: [+, 0, -, 0] (左右电机)
纯旋转: [-, -, -, -] (同向旋转)
```

## 使用说明

### 1. 编译配置
在 `robot_task.c` 中添加测试任务：

```c
#include "chassis_motor_integration_test.h"

void Robot_task_init(void)
{
    // 启用集成测试（注释掉其他测试）
    osThreadDef(chassis_motor_integration_test, Chassis_motor_integration_test_task, osPriorityNormal, 0, 2048);
    osThreadId test_handle = osThreadCreate(osThread(chassis_motor_integration_test), NULL);
}
```

### 2. 硬件连接
确保以下硬件正确连接：
- CAN1总线连接4个底盘电机 (ID: 0x201-0x204)
- UART1用于调试输出
- 电机供电正常

### 3. 运行测试
1. 编译并下载程序
2. 打开串口调试工具 (波特率115200)
3. 观察测试日志输出
4. 验证电机实际转动情况

### 4. 日志解读

**正常输出示例**:
```
[CHASSIS-MOTOR-TEST] ========================================
[CHASSIS-MOTOR-TEST]   Chassis-Motor Integration Test Started
[CHASSIS-MOTOR-TEST] ========================================
[CHASSIS-MOTOR-TEST] ✓ Chassis and Motor tasks created successfully
[CHASSIS-MOTOR-TEST] === Phase 1: Initialization Test ===
[CHASSIS-MOTOR-TEST] ✓ Message center registration successful
[CHASSIS-MOTOR-TEST] ✓ Phase 1 test passed
```

**错误输出示例**:
```
[CHASSIS-MOTOR-TEST] ✗ No chassis feedback received
[CHASSIS-MOTOR-TEST] ✗ Phase 2 test failed
```

## 故障排除

### 常见问题

#### 1. 消息中心注册失败
**症状**: `Message center registration failed`
**原因**: 
- 消息中心未正确初始化
- 话题名称冲突
- 内存不足

**解决方法**:
```c
// 检查消息中心是否在其他地方已初始化
// 确保话题名称唯一
// 增加堆栈大小
```

#### 2. 任务创建失败
**症状**: `Failed to create tasks`
**原因**:
- 堆栈空间不足
- 任务优先级冲突
- 系统资源耗尽

**解决方法**:
```c
// 增加任务堆栈大小到2048或更大
// 调整任务优先级
// 检查系统内存使用情况
```

#### 3. 电机无响应
**症状**: `All motor speeds are zero`
**原因**:
- CAN总线连接问题
- 电机ID配置错误
- 电机驱动初始化失败

**解决方法**:
```c
// 检查CAN总线接线
// 验证电机ID设置 (0x201-0x204)
// 确认电机驱动初始化成功
```

#### 4. 数据传递异常
**症状**: `No motor speed update available`
**原因**:
- 静态全局变量接口问题
- 任务同步时序问题
- 数据更新标志位异常

**解决方法**:
```c
// 检查motor_chassis_interface模块
// 调整任务运行频率
// 验证标志位清除逻辑
```

#### 5. 运动学解算错误
**症状**: `Kinematics pattern validation failed`
**原因**:
- 全向轮布局配置错误
- 运动学参数设置问题
- 电机安装方向错误

**解决方法**:
```c
// 检查chassis.c中的运动学模型
// 验证轮子半径和底盘半径参数
// 确认电机安装和转动方向
```

## 性能指标

### 时延要求
- 消息传递延迟: < 5ms
- 运动学解算时间: < 1ms
- 电机响应延迟: < 10ms

### 测试频率
- Chassis Task: 500Hz
- Motor Task: 1000Hz
- Integration Test: 2Hz (测试指令发送)

### 通过标准
每个测试阶段的通过率应达到 > 95%

## 扩展测试

### 压力测试
可通过修改测试频率和指令复杂度进行压力测试：
```c
// 高频测试
osDelay(10);  // 100Hz测试频率

// 复杂指令测试
Send_chassis_command(vx_complex, vy_complex, wz_complex, mode);
```

### 长期稳定性测试
运行测试24小时以上，监控：
- 内存泄漏
- 任务调度异常
- 数据传递稳定性

### 边界条件测试
测试极限值和异常输入：
```c
// 最大速度测试
Send_chassis_command(5.0f, 5.0f, 5.0f, CHASSIS_NO_FOLLOW);

// 零值测试
Send_chassis_command(0.0f, 0.0f, 0.0f, CHASSIS_ZERO_FORCE);

// 快速切换测试
for (int i = 0; i < 100; i++) {
    Send_chassis_command(1.0f, 0.0f, 0.0f, CHASSIS_NO_FOLLOW);
    osDelay(1);
    Send_chassis_command(0.0f, 1.0f, 0.0f, CHASSIS_FOLLOW_GIMBAL);
    osDelay(1);
}
```
