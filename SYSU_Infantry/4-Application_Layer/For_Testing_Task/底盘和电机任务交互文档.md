# Motor Task 和 Chassis 模块拆分总结

## 概述
根据 README 的规划，我们已经成功将原本的 Motor Task 系统进行了拆分和解耦，将底盘解算功能从 Motor Control 模块中分离，创建了独立的 Chassis 功能模块和 Chassis Task。

## 拆分后的架构

### 1. Motor Task + Motor Control 模块
**文件位置：**
- `4-Application_Layer/Execution/Motor_Task/motor_task.c`
- `3-Function_Module_Layer/Motor_Control/motor_control.c`

**主要职责：**
- 纯 CAN 发送任务，频率 1000Hz
- 控制所有电机的目标值
- 通过静态全局变量接收底盘电机的目标值（来自 Chassis Task）
- 通过发布订阅模型接收云台和发射机构的控制指令（来自决策层）
- 负责电机控制模式的切换和 PID 参数配置

**关键改动：**
- 移除了底盘运动学解算逻辑
- 新增 `Motor_control_handle_chassis_motors()` 函数，从静态全局变量获取底盘电机目标值
- 保留云台和发射机构的控制逻辑

### 2. Chassis Task + Chassis 模块
**文件位置：**
- `4-Application_Layer/Execution/Chassis_Task/Chassis_task.c`
- `3-Function_Module_Layer/Chassis/chassis.c`

**主要职责：**
- 底盘运动学解算，频率 500Hz
- 通过发布订阅模型接收决策层的底盘控制指令
- 支持可配置的底盘类型框架（全向轮、麦克纳姆轮、差速轮）
- 当前实现全向轮底盘解算算法
- 通过静态全局变量传递解算结果给 Motor Task

**关键特性：**
- 模块化设计，支持多种底盘类型
- 独立的运动学解算逻辑
- 可配置的底盘物理参数

### 3. Motor-Chassis 接口模块
**文件位置：**
- `3-Function_Module_Layer/Motor_Control/motor_chassis_interface.c`
- `3-Function_Module_Layer/Motor_Control/motor_chassis_interface.h`

**主要职责：**
- 定义 Motor Task 和 Chassis Task 之间的静态全局变量接口
- 提供电机速度目标值传递
- 提供电机控制模式和场景配置传递
- 通过标志位实现数据更新检测

## 数据流向

```
决策层 (Decision Making)
    ↓ (发布订阅)
Chassis Task
    ↓ (底盘解算)
Chassis 模块
    ↓ (静态全局变量)
Motor Task
    ↓ (电机控制)
Motor Control 模块
    ↓ (CAN发送)
底盘电机
```

## 使用的 API 接口

### 发布订阅模型 API（来自现有系统）
- `Sub_register()` - 注册订阅者
- `Pub_register()` - 注册发布者
- `Sub_get_message()` - 获取消息
- `Pub_push_message()` - 推送消息

### 静态全局变量接口 API（新增）
- `Motor_chassis_interface_init()` - 初始化接口
- `Chassis_set_motor_speeds()` - Chassis Task 设置电机速度
- `Chassis_set_motor_config()` - Chassis Task 设置底盘模式
- `Motor_get_chassis_speeds()` - Motor Task 获取电机速度
- `Motor_get_chassis_config()` - Motor Task 获取底盘模式

### DJI电机驱动 API（已适配）
- `Djimotor_switch_scene()` - 切换电机场景（现在直接使用chassis_mode_e）
- `Djimotor_update_scene_config()` - 更新场景配置
- `Djimotor_set_target()` - 设置电机目标值

## 底盘类型支持

当前系统支持三种底盘类型的配置：

1. **全向轮底盘 (CHASSIS_TYPE_OMNI)** - 当前实现
   - 支持任意方向的平移和旋转
   - 四轮布局：前后左右

2. **麦克纳姆轮底盘 (CHASSIS_TYPE_MECANUM)** - 已实现算法
   - 支持任意方向的运动
   - 四轮布局：左前、右前、左后、右后

3. **差速轮底盘 (CHASSIS_TYPE_DIFFERENTIAL)** - 已实现算法
   - 仅支持前进后退和原地旋转
   - 两轮布局：左轮、右轮

## 运行频率

- **Motor Task**: 1000Hz - 确保电机控制的实时性
- **Chassis Task**: 500Hz - 平衡解算精度和性能

## 优势

1. **模块解耦**: 底盘解算和电机控制分离，职责清晰
2. **可扩展性**: 底盘类型可配置，易于支持新的底盘类型
3. **维护性**: 各模块功能单一，便于调试和维护
4. **性能优化**: 不同频率运行，合理分配计算资源
5. **架构清晰**: 遵循分层架构设计原则

## 重要更新：场景枚举统一

**问题**: 原系统中存在 `Djimotor_scene_e` 和 `chassis_mode_e` 两个高度重合的枚举类型，造成冗余和混淆。

**解决方案**: 
1. **保留 `chassis_mode_e`** - 作为统一的底盘控制模式枚举
2. **重定义 `Djimotor_scene_e`** - 改为 `chassis_mode_e` 的别名，保持DJI电机驱动的兼容性
3. **简化接口** - 移除场景映射函数，直接使用 `chassis_mode_e` 作为电机场景

**优势**:
- **统一性**: 整个系统只使用一套底盘模式定义
- **兼容性**: DJI电机驱动接口保持不变
- **简洁性**: 减少不必要的枚举转换逻辑

**映射关系**:
- `CHASSIS_ZERO_FORCE` - 零力矩模式
- `CHASSIS_NO_FOLLOW` - 不跟随模式（对应原键盘鼠标模式）
- `CHASSIS_FOLLOW_GIMBAL` - 跟随云台模式
- `CHASSIS_ROTATE` - 小陀螺模式

## 注意事项

1. Chassis Task 必须在 Motor Task 之前启动，确保接口正确初始化
2. 静态全局变量使用标志位进行更新检测，避免重复处理
3. 保持与现有发布订阅模型 API 的兼容性
4. 现在整个系统统一使用 `chassis_mode_e`，简化了模式管理
5. DJI电机驱动的场景配置已更新为直接使用 `chassis_mode_e` 枚举值
