# 快速启动指南

本文档用于第一次拿到本工程时快速完成“能编译、能下载、能进入安全运行状态、能逐步打开模块”的检查。当前主工程位于仓库内层目录 `SYSU_Infantry/`。

## 1. 准备环境

需要安装：

- CMake `>= 3.22`
- Ninja
- Arm GNU Toolchain，并确保 `arm-none-eabi-gcc` 在 `PATH` 中
- STM32CubeMX，用于查看或修改 `SYSU_Infantry.ioc`
- 烧录/调试工具，例如 STM32CubeProgrammer、ST-Link、J-Link、OpenOCD、CLion 或 VS Code Cortex-Debug

检查工具链：

```bash
arm-none-eabi-gcc --version
cmake --version
ninja --version
```

## 2. 编译工程

在仓库根目录执行：

```bash
cd SYSU_Infantry
cmake --preset Debug
cmake --build --preset Debug
```

构建产物通常位于：

```text
SYSU_Infantry/build/Debug/SYSU_Infantry.elf
SYSU_Infantry/build/Debug/SYSU_Infantry.map
```

Release 构建：

```bash
cmake --preset Release
cmake --build --preset Release
```

## 3. 默认启动链路

固件上电后主要启动链路：

```text
main.c
  -> HAL/CubeMX 外设初始化
  -> Can_init()
  -> DWT_Init(168)
  -> MX_USB_DEVICE_Init()
  -> MX_FREERTOS_Init()
     -> Robot_task_init()
        -> 创建队列
        -> 创建 INS / Watchdog / Motor / Referee / Decision / Chassis / Gimbal / Shoot / Buzzer 任务
```

`Robot_task_init()` 是当前整车任务入口。快速排查时优先看它创建了哪些任务。

## 4. 上电前硬件检查

最小检查项：

- 主控板供电正常。
- CAN1/CAN2 接线、终端电阻、电机 ID 与代码一致。
- 调试串口或 RTT 可用。
- 云台、底盘、发射机构处于安全机械状态。
- 首次测试时架空底盘或拆下危险负载。
- 摩擦轮和拨弹盘不要带弹测试。

当前默认电机分布可参考：

| 模块 | 电机 | CAN |
| --- | --- | --- |
| 底盘 | 4 个 M3508，反馈 `0x201-0x204` | CAN1 |
| 云台 Yaw | GM6020，反馈 `0x205` | CAN1 |
| 云台 Pitch | GM6020，反馈 `0x206` | CAN2 |
| 发射 | 2 个 M3508 + 1 个 M2006，反馈 `0x201-0x203` | CAN2 |

## 5. 最小安全启动建议

第一次下载后建议按顺序验证：

1. 保持遥控器急停或让决策层输出零力矩。
2. 确认系统没有反复 `ERROR_FATAL`。
3. 确认 CAN 初始化没有 Critical 错误。
4. 确认 `Motor_control_task` 运行，但电机在 `MOTOR_STOP` 或零目标下无输出。
5. 确认 INS 能进入 `INS_STATE_READY`。
6. 再逐个启用底盘、云台、发射动作。

## 6. 调试输出

当前工程常见调试通道：

- `Uart_printf()`：BSP USART 非阻塞打印。
- `printf()`：`main.c` 中 `_write()` 当前重定向到 `huart1`。
- `ERROR_INFO/WARN/RAISE/CRITICAL/FATAL`：错误系统输出。
- SEGGER RTT/SystemView：用于高频或任务调度调试。
- VOFA：用于波形观察。

注意：高频任务中不要无节制打印，否则会影响控制周期。

## 7. 测试任务说明

测试任务位于：

```text
4-Application_Layer/For_Testing_Task/
```

当前需要特别注意：

- `message_test_task.c` 可用于测试 `Message_Center` 发布订阅模型。
- `chassis_motor_integration_test.c` 是历史 Pub/Sub 测试任务，当前主底盘任务使用 FreeRTOS Queue，不会自动读取 `chassis_cmd` 话题。
- `rc_test_task.c` 当前内容实际是 DJI 电机库验收测试，不是遥控器测试。
- `can_motors_test_task.c` 主体已注释，保留为历史草稿。

如果要启用测试任务，请在 `Robot_task_init()` 中创建对应任务，并确认不会与主控制任务同时争用同一电机。

## 8. 推荐验证顺序

### 阶段 A：编译与空载

- 编译通过。
- 下载后系统不复位循环。
- CAN、USART、USB 初始化没有 Critical 错误。
- 急停状态下所有电机无力矩。

### 阶段 B：单设备

- 单独验证 DJI 电机反馈是否在线。
- 单独验证 INS 数据是否更新。
- 单独验证遥控器/图传链路数据是否更新。
- 单独验证裁判系统或视觉通信。

### 阶段 C：单模块

- 底盘：先 `CHASSIS_NO_FOLLOW` 小速度测试。
- 云台：先 `GIMBAL_GYRO_MODE` 小角度测试。
- 发射：先无弹测试摩擦轮，再测拨弹盘。

### 阶段 D：整车联调

- 启用决策任务统一下发命令。
- 逐步测试跟随云台、小陀螺、视觉模式、功率限制。
- 记录异常日志和回滚方式。

## 9. 常见问题

| 问题 | 排查 |
| --- | --- |
| CMake 找不到编译器 | 检查 Arm GNU Toolchain 是否加入 `PATH` |
| 电机无响应 | 检查 `Motor_control_task`、CAN 接线、电机 ID、`Djimotor_Calc_Output()` 是否被调用 |
| 上电后电机乱动 | 先确认默认命令是否零力矩，检查任务是否读取到旧目标 |
| INS 不 Ready | 检查 BMI088/HWT 驱动选择、SPI/I2C 接线、DWT 初始化 |
| 视觉模式没反应 | 检查 `USE_VISION_USB`、USB CDC、CRC、`Is_Vision_Online()` |
| 频繁急停 | 检查 `ERROR_FATAL`、遥控器 pause/拨轮急停、看门狗离线回调 |

## 10. 上车原则

- 先低速，再高速。
- 先架空，再落地。
- 先单模块，再整车。
- 先无弹，再带弹。
- 任何 Fatal 或电机离线问题解决前，不进行高速场地测试。
